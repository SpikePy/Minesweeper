# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Classic Minesweeper as a single static page: all HTML, CSS and JS live in `index.html` (no build step, no dependencies, no package manager, no tests, no linter). It is deployed as-is via GitHub Pages (https://spikepy.github.io/Minesweeper). To run it, open `index.html` in a browser. Keep the game itself in that one file.

Assets: `faces/*.png` are the DOOM-style face button states (`ok`, `ouch`, `dead`, `win`; Doom status-bar faces, set by `setFace`). `doom/` holds the rest of the DOOM style, taken from Freedoom 0.13.0 (BSD, `doom/COPYING-freedoom.txt`; keep that file): `wall.png` (generated from the skulls of texture SKULWALL by image quilting into one seamless 512×512 tile, snapped to the Doom palette, shown at 1024px so the repeat is hard to spot), `plates/P*.png` (9 plates for covered cells, picked at random per cell in `render()` via `pickPlates()` from `PLATES` (capped per game by `PLATE_MAX`: the bloody P10 and P12 at most 2 times each), set as the CSS variable `--plate`: panels cut from texture STARGR2 with an even 3px dark frame, two with drawn blood (P10 smear, P12 crack with blood), in the Doom palette; the IDs match the plate picker they were chosen from), `mine.png` (mine, drawn for this project in the Doom palette), `boom.png` (hit mine: Freedoom rocket fireball MISLB0 shrunk to icon size, with spikes of the mine flying off, Doom palette), `flag.png` (skull banner = flag, drawn for this project in the Doom palette), `gear.png` (drawn for this project) and the sounds `open|area|flag|unflag|win|boom|die|start|menu|setting|close.wav` (open and area: DSITEMUP pitched down to 0.8; flag DSITEMUP; unflag DSSWTCHX; win DSGETPOW; boom DSBAREXP pitched down to 0.75; die DSPLDETH; start DSTELEPT; menu DSPSTOP; setting and close DSPISTOL; 8-bit WAV, 11025 Hz). They were extracted from `freedoom2.wad` (lump names above); to swap one, extract another lump the same way rather than using id Software's original Doom assets. PWA support: `manifest.webmanifest`, `icons/` (PNGs generated from the `favicon.svg` flag) and `sw.js`. The service worker is network-first for same-origin GETs with a cache fallback, so updates ship without bumping anything; it ignores cross-origin requests (Supabase). If you add a file the page needs offline, add it to `SHELL` in `sw.js` and bump `CACHE`. Service worker and install only work over HTTP(S), not `file://` (`python3 -m http.server`).

`supabase/setup.sql` is the one-time schema for the shared high-score table; it is run by hand in the Supabase SQL editor, not by any tooling.

## Architecture of `index.html`

All script code is in one IIFE. Main pieces:

- **State** is a set of closure variables (`W, H, M, cells, mode, flagMode, rec, replaying, ...`). Each cell is `{ mine, open, flag, n }`; `cellEls[i]` is its DOM node. `drawCell(i)` re-renders one cell from its state; `render()` rebuilds the whole board.
- **All game actions go through `act(a, i)`** (`'o'` = open, or chord on an open number; `'f'` = toggle flag). Input handlers (`handlePrimary`, right click, long press) only decide which action; `act` records it into `rec` as `[ms since first open, 0|1, cell]` and applies it. Mines are placed on the first open by `generate(start)` (with `Math.random`).
- **Replays (demos):** a win stores `makeDemo()` = `{ w, h, m, mines: [cell indices], ev: rec }` with the score. `playDemo(level, entry)` rebuilds the board from `mines` (no generation) and plays the events through the same `act`, with `replaying = true` (user input ignored, no score saved, the win shows the recorded `ms`). Playback runs on its own clock (`replay.pos`, `replayPos()`, scaled by `replaySpeed` 1/0.5/0.25, frozen while paused) with one `setTimeout` for the next due event (`scheduleReplay`/`stepReplay`); the timer display follows that clock via `elapsedMs()`. The `#replayBar` below the board (pause/resume, restart, speed) is updated by `updateReplayBar()`. `newGame()` calls `stopReplay()`. A demo is self-contained, so changes to the generator never break old replays; changes to `act`/`chord`/`reveal` semantics could.
- **No-guess generation** (between the `Spielfeld ohne Raten` markers): `generate` places mines outside the start cell's 3×3 area, then runs `solve`, a solver limited to what the player can see (single-number rule, enumeration around each number, then the whole frontier plus the mine counter). When it gets stuck, `perturb` moves one mine at the frontier; after `PERTURBS` failed moves it re-rolls. Work is capped by `BUDGET / (W*H)` steps; if that runs out (very dense custom boards) it uses the best board found and shows `mayGuess`. The game mode `logic` (`ms-logic`, "Pure logic") makes `solve` stricter: step 2 runs without the remaining-mines bound and step 3 (whole frontier + mine counter) is skipped, so every board can be finished from local deductions alone; the default "Standard" keeps the full solver. To benchmark, extract the code between those markers plus `neighbors` and run it in Deno (`deno`, on the PATH); the section reads the free variable `logic`, so define it.
- **Levels:** `PRESETS` (`easy|medium|hard`) defines the board sizes, and `LEVELS` is derived from it. The sizes are also written into the `I18N` labels (`easy`, `medium`, `hard` in both languages) and the README, and the level names appear in the `setup.sql` check constraint, so change them all together. Custom boards are clamped to 5–50 × 5–30.
- **Replays** and **custom boards** never count for high scores.
- **High scores** (top 10 per preset level, `TOP`; shown in an overlay via `showScores`: after every win through `afterRound()` (not after a loss, not for replays), and from the 🏆 button; `newGame()` closes it): there are two lists, `scores.local` (localStorage, `ms-top-<level>`) and `scores.online` (Supabase), and the overlay shows one of them (`view`, toggled by the "This device | Online" buttons, default local, remembered in `ms-view`). `loadScores()` reloads both; the online part goes through Supabase's REST API (`api()` is a thin `fetch` wrapper using `SUPABASE_URL`/`SUPABASE_KEY`), and `online` is `null` before the first load and `false` if Supabase is unreachable. On a win, `checkRank()` first reloads (`loadScores`), computes the rank in each list and shows both (`newBest`); the score is saved only to the lists where it ranks within `TOP` (`pending.local` / `pending.online`, written by `submitScore()`). Times are milliseconds (`ms`, measured with `performance.now()`); the table keeps whole seconds in `time` plus `ms`, the `demo` (jsonb), `device` (`pc|mobile|tablet`, from `deviceType()` via the user agent, shown as an inline SVG from `DEVICE_ICONS` in the list), `clicks` (`rec.length`, i.e. recorded board actions; for older entries `normEntry` derives it from `demo.ev.length`) and `logic` (game mode; boolean, default false). Both lists only ever show the current game mode: the local list key is `topKey(level, logic)` (`ms-top-<level>` for Standard, `ms-top-logic-<level>` for Pure logic) and the online query filters `logic=eq.<bool>`; switching the mode starts a new game and reloads the lists; `supabase/migrate.sql` upgrades older tables. `schema` indexes `COLS` (the selected columns per table version): if a query is rejected with a 4xx (columns missing), it steps down (4 = all, 3 = no logic, 2 = no clicks, 1 = no device, 0 = whole seconds without demos), and the POST only sends the columns of that level. Below 4 the online list can't tell the modes apart, so `onlineReady()` disables it (no list, no POST) in Pure logic mode. `readBest()` migrates the old single best-time format (`ms-best-<level>`). The publishable key in the source is intentionally public; RLS in `setup.sql` only allows select + insert. If you change score fields, keep `setup.sql` and `migrate.sql` in sync (level names `easy|medium|hard`, device names, name length 1–16, clicks range, demo size limit), and add a step to `COLS`.
- **Settings** (`#settingsOverlay`, opened by the ⚙️ button `settingsBtn` next to 🚩 in the controls row, `showSettings`): volume slider, language buttons, the style buttons (`#lookMode`, Classic / DOOM), the difficulty select (`diffSel`, `#difficulty`), the game mode buttons (`#logicMode`, Standard / Pure logic) and the player name. This is the only place for all of them; the main page only has ⚙️, 🚩 and 📲, plus the custom size inputs (`customBox`) when the custom difficulty is selected. `showSettings(true)` fills the volume and name from storage; the name input writes `ms-name` on `change` (empty keeps the old name). Without a stored name, a win asks for one in the scores overlay (`nameForm`).
- **Styles** (`look`, `ms-style`, `setLook()`, settings buttons `#lookMode`): `classic` (default) and `doom`. `setLook` sets `data-look` on `<html>`; the DOOM CSS (`:root[data-look="doom"]` colour tokens, wall background, red title) keys off that. Faces: `setFace(f)` shows `SMILEYS[f]` as text (class `emoji`) or `faces/<f>.png`. Icons: `icon(name)` returns the emoji from `EMOJI` or `<i class="di di-<name>">` (sprite via CSS); used by `drawCell`, `updateMines`, the title, 🚩 and ⚙️ buttons, and `setLook` swaps them on the current board (wrong-flag ❌ cells stay).
- **Sounds:** `sound(name)` (`open`, `area`, `flag`, `unflag`, `win`, `boom`, and DOOM only: `die`, `start`, `menu`, `setting`, `close`; `synth` skips a name that `SOUNDS[look]` doesn't have, so Classic stays silent for those). Classic synthesizes them with Web Audio (`synth`, `SOUNDS.classic`); DOOM plays `doom/<name>.wav` through a cloned `Audio` element, and if a file can't load (`NotSupportedError`, e.g. some browsers on `file://`) it switches for good to the synthesized `SOUNDS.doom`. The `AudioContext` is created lazily on the first synthesized sound (inside a user gesture, so autoplay rules allow it), and `volume` (0–100, `ms-volume`, default 50) scales the output quadratically for both; 0 skips sounds entirely. Hooks: `act` (open/area, by how many cells it opened), `toggleFlag`, `win`, `lose` (`boom`, then `die` 250 ms later unless a new game started), `newGame` (`start`, not on page load: `booted`), the ⚙️ and 🏆 buttons (`menu`), closing the settings or scores overlay by ✕, a click beside it or Escape (`close`; not when `newGame` closes it), toggling flag mode (🚩 button or F) and volume, language, style, game mode and name changes (`setting`; the game mode calls `newGame(true)` so `start` stays silent; difficulty starts a new game and plays `start` instead); replays play the sounds too.
- **i18n:** all UI strings live in `I18N.de` / `I18N.en` (add every new key to both). Static elements use `data-i18n`, `data-i18n-title`, `data-i18n-placeholder`, `data-i18n-aria`; `setLang()` re-applies them. Messages are stored as a key (`setMessage(key, arg)`) so they re-translate on language switch — don't write translated text into the DOM directly.
- **Input:** pointer events: mouse and pen act on press, touch on release (click opens, right click toggles a flag or chords on numbers), long press = flag, flag mode (`flagMode`, toggled by the 🚩 button or `F`) makes taps toggle flags, keyboard `R`/`F2` for new game, `Escape` closes the settings or scores overlay (the keyboard shortcuts are ignored while focus is in an input/select).
- **Persistence:** always go through the `store` wrapper (try/catch around localStorage). Keys are prefixed `ms-` (`ms-lang`, `ms-mode`, `ms-name`, `ms-view`, `ms-volume`, `ms-logic`, `ms-style`, `ms-top-*`).
